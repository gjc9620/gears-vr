# 右侧绘制调用存在，主要裁剪区域覆盖右侧

2026-10-12，原版关卡、第一人称 Mod 已恢复，用户要求永久关闭 DLSS。实际双眼像素仍未通过：窗口左半显示完整场景，右半黑色。

## 新增观察手段

通过本机 D3D12 真实命令列表的虚表取得 Reset、RSSetViewports、RSSetScissorRects、DrawInstanced、DrawIndexedInstanced 入口。可选 `--viewport-diagnostics` 保留原参数与返回值，只记录调用；与有界双视图提交组合，不与镜头运动实验组合。

命令列表有固定 256 个跟踪槽，Reset 清空其矩形；绘制统计区分全屏、左、右及其他区域。第二版额外保存试验消费函数线程范围内的实际 viewport/scissor 配对，最多 64 种，不逐次写磁盘，也不无限分配内存。被跟踪的列表超过容量会明确报告 overflow/untracked_draws，因此不是完整 GPU 调用审计。

`phase=1` 仅表示调用发生在已登记双视图渲染器的原消费函数、同一线程范围内。其他线程或延迟 RHI 工作可能落在 phase=0，不能把 phase=0 当作纯单视图基线。Draw 计数是 CPU API 调用数，不是顶点数、GPU 完成数或最终像素证明。尚未覆盖 ExecuteIndirect、目标资源、Clear 和最终合成。

## 两轮现场证据

第一轮 PID 30160，10 秒双视图共 1,722 次提交，消费／准备／销毁各 1,722；状态已释放、池为空。17 个入口经独立验证恢复。试验范围内左／右 viewport 分别记录 407,036／410,875 次直接绘制，但 scissor 全部归为“其他”，不足以判断裁剪。

第二轮 PID 7276，10 秒双视图共 1,760 次提交，消费／准备／销毁各 1,760；状态已释放、池为空，17 个入口再次恢复。原源视图保持，停止后恢复单视图。实际矩形记录无溢出：

| Viewport，x/y/宽/高 | Scissor，x/y/宽/高 | 试验范围内绘制调用 |
| --- | --- | ---: |
| 0/0/960/1080 | 0/0/16384/16384 | 505,067 |
| 960/0/960/1080 | 0/0/16384/16384 | 505,925 |
| 0/0/1920/1080 | 0/0/16384/16384 | 7,248 |

还有少量对应左右位置的小裁剪区域，以及不同尺寸的后处理／辅助区域；仅凭尺寸不命名具体渲染 pass。命令列表跟踪容量溢出 262,460 次，未跟踪绘制 1,438,608 次，所以不能据此排除所有未捕获路径的错误。

上述大量右侧绘制的裁剪范围覆盖右半屏，反驳了“这些右侧调用都被左侧 scissor 挡住”的猜测。右 viewport 本身正确也不能证明其绑定目标宽度足够、资源内容正确，或最终合成保留了右半部。

## 验证与本地证据

- 独立矩形测试涵盖左右识别、非有限值、右 viewport 配左 scissor、Reset 清空、命令列表容量上限、实际矩形重复累计、非试验范围不入直方图、64 种矩形容量上限。
- D3D12 自测使用真实设备与命令列表，验证新增入口转发及停止后的入口恢复；没有构造绘制 PSO，不宣称离线自测执行了真实 Draw。
- 八项既有提交与持续生命周期分析测试通过。
- `analysis/runtime/viewport-combined-30160.*` 与 `viewport-rects-7276.*` 保存现场统计、生命周期分析和入口核验。
- `analysis/game-io/frames/20261012-174634-7e1a53fc.jpg`、`20261012-175602-cc214a78.jpg` 是试验中途的游戏窗口采集。
