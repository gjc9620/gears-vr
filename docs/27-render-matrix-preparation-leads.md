## 已确认的代码关系

- 消费入口 0x15a80c 的默认绘制候选 0x11908c 调用 0x1fc060；另一绘制候选 0xe29520 也调用同一准备函数。当前没有动态区分具体绘制分支。
- 0x1fc060 从渲染对象 +0x68 取出视图数组，以 0xD30 为元素步长。视图 +8 处的指针参与后续历史数据保存和判定；其具体类型还未证明。
- 0x1fc300 / 0x1fc30d 从当前视图 +0x70 / +0x90 复制共 64 字节到该关联对象 +0x210 / +0x230。其他路径还从视图 +0xB0 / +0xD0 复制共 64 字节到关联对象 +0xE0 / +0x100。代码包含时间值、视图尺寸和其他状态判定。因此不能把双眼实现简化为一次矩阵写入；还需核对各眼关联状态和派生数据。
- 准备函数早期调用 0x18c3b4。后者按设置选择不同路径，其中一条是 0x18c3f8 → 0x18c460 → 0x18c4d0。
- 0x18c460 将输入帧序号对样本数取余后加一，分别以基数 2 和 3 调用 0x18c4d0，然后减去 0.5，写入两个浮点输出。0x18c4d0 通过反复取余、除以基数、累乘权重得到数值；运行时常量读取确认权重初值为 1.0、中心偏移为 0.5。

上述数值算法符合基数 2/3 的 radical-inverse 二维序列。结合渲染位置，它是帧采样偏移的候选；没有动态证明本轮调用了这个设置分支，也没有追到输出进入视图 +0xD0 / +0xD4 的完整写入链。因此不把它直接认定为已经确认的抗锯齿矩阵抖动。
