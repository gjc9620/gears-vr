# PathChoice 源头局部变换：私有实验计划

2026-10-17。仅复核 docs/122 和已验证的 chunks；未读取当前进程、启动游戏或 IDA。历史模块基址为 `0x140000000`，代码节 SHA256 为 `911ab9bcb24cc078420400369a78ffd3f747d915e42c4935a5c82c2dcecc6ae6`；证据在 ignored `analysis/ida/ui-pathchoice-20261017/`。这些结论不能替代当前字节认证。

`RVA 0x296188` 不直接重设矩阵：它保存/缩放 canvas 首浮点值，经 `+0x3f0` 调用 `0x2c6ecc`，再调用 `+0x4b0`，最后恢复该浮点值。`0x2c6ecc` 为每个子节点构造局部矩阵，在 `0x2c73f4` 调用 `0x2c7650`。后者追加80字节栈项，将输入64字节矩阵乘旧栈顶，并在新项 `+0x40` 重算哈希。因此这里是继承合成，不是绝对覆盖；整个80字节记录不能当64字节矩阵改写。

实际矩阵 pop 在 `0x2c7430–0x2c744b`：调用 `0x138d70`，参数为 `RCX=canvas+0x38, EDX=count-1, R8D=1, R9D=0x50`，第五参数8。先前的 `0x2c7534` 是另一整数栈操作。不得使用修改首栈项的 `0x2c3ea8`，其作用域跨兄弟scene。

最小实验复用已认证 root adapter 外层：仅对当前 PathChoice/client/canvas/owner 成立的最外层调用，正常 push 一次小幅向下平移，原调用恰好一次，再按上述引擎删除路径 pop；不新增GPU receipt。TLS按canvas防重复，同canvas出现其他scene嵌套须明确隔离或判实验失败。先零位移，再小位移，退出后回到零；四段投影同量变化、相对布局与裁剪正确、后续非目标scene不变才继续调中心位置。

实施前须复核当前 adapter、虚表槽、上述完整函数chunks及 push 的 `0x2c789c`、pop 的 `0x138d70` 实现/ABI；后两者不能只凭调用点推定完整契约。Windows x64：push 的 RCX 为canvas、RDX指向64字节输入矩阵；返回值语义未定，不使用。保持shadow space、对齐、非易失寄存器及原返回位。

记录初始深度与完整父项，push后验证深度+1；退出仅在本层仍为预期栈顶时pop，并重取可能扩容后的地址验证父项，不回写旧TArray头。恢复作用域覆盖正常退出及已明确支持的展开路径；不能声称普通RAII覆盖任意SEH，异常中止/栈不平衡应停用实验而非盲删。仍需实际证明排队item保留组合变换、特殊分支不绕过；以现有delta和双眼截图验证。
