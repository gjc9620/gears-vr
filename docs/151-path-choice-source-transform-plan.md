# PathChoice 源头局部变换：私有实验计划

2026-10-17。仅复核 docs/122 和已验证的 chunks；未读取当前进程、启动游戏或 IDA。历史模块基址为 `0x140000000`，代码节 SHA256 为 `911ab9bcb24cc078420400369a78ffd3f747d915e42c4935a5c82c2dcecc6ae6`；证据在 ignored `analysis/ida/ui-pathchoice-20261017/`。这些结论不能替代当前字节认证。

`RVA 0x296188` 不直接重设矩阵：它保存/缩放 canvas 首浮点值，经 `+0x3f0` 调用 `0x2c6ecc`，再调用 `+0x4b0`，最后恢复该浮点值。`0x2c6ecc` 为每个子节点构造局部矩阵，在 `0x2c73f4` 调用 `0x2c7650`。后者追加80字节栈项，将输入64字节矩阵乘旧栈顶，并在新项 `+0x40` 重算哈希。因此这里是继承合成，不是绝对覆盖；整个80字节记录不能当64字节矩阵改写。

实际矩阵 pop 在 `0x2c7430–0x2c744b`：调用 `0x138d70`，参数为 `RCX=canvas+0x38, EDX=count-1, R8D=1, R9D=0x50`，第五参数8。先前的 `0x2c7534` 是另一整数栈操作。不得使用修改首栈项的 `0x2c3ea8`，其作用域跨兄弟scene。

最小实验复用已认证 root adapter 外层：仅对当前 PathChoice/client/canvas/owner 成立的最外层调用，正常 push 一次小幅向下平移，原调用恰好一次，再按上述引擎删除路径 pop；不新增GPU receipt。TLS按canvas防重复，同canvas出现其他scene嵌套须明确隔离或判实验失败。先零位移，再小位移，退出后回到零；四段投影同量变化、相对布局与裁剪正确、后续非目标scene不变才继续调中心位置。

实施前须复核当前 adapter、虚表槽、上述完整函数chunks及 push 的 `0x2c789c`、pop 的 `0x138d70` 实现/ABI；后两者不能只凭调用点推定完整契约。Windows x64：push 的 RCX 为canvas、RDX指向64字节输入矩阵；返回值语义未定，不使用。保持shadow space、对齐、非易失寄存器及原返回位。

记录初始深度与完整父项，push后验证深度+1；退出仅在本层仍为预期栈顶时pop，并重取可能扩容后的地址验证父项，不回写旧TArray头。恢复作用域覆盖正常退出及已明确支持的展开路径；不能声称普通RAII覆盖任意SEH，异常中止/栈不平衡应停用实验而非盲删。仍需实际证明排队item保留组合变换、特殊分支不绕过；以现有delta和双眼截图验证。

## 两个栈 helper 的历史复核补充

依据 `analysis/ida/path-choice-stack-20261017/` 的已验证chunks。`0x2c789c` 使用RDX指向TArray（RCX在本体未用），先将count加一，必要时以stride80、alignment8扩容，RAX返回新增项；不初始化整项。结合`0x2c7650`，已证实记录`+0..0x3f`为组合矩阵、`+0x40`为对64字节计算的32位哈希；`+0x44..0x4f`用途未证，不伪造缓存字段。外包正常push让引擎维护矩阵及哈希，比直接写栈顶合理；push返回值不作为成功凭证，必须查深度和新项。

`0x138d70` ABI为(array,index,count,stride,alignment)，第五参数在入口栈`+0x28`；本函数压栈后从`+0x80`读取。尾删一项跳过搬移，随后减count，并可能缩容/重分配；不是单纯count--。未见元素析构或边界校验，调用方必须保证参数有效。它及push均进入分配器，现有chunks不足以保证不抛异常、不终止或分配失败回滚。不得恢复旧data/capacity，也不把地址不变当恢复条件。当前完整字节复核通过后，root外包一层方案仍成立；初次实验可另要求容量足够且预测尾删不触发缩容，缩小异常面，但原子节点自身仍可能分配，不能声称整个调用无异常。

## 自动集成与当前限制

`da060b0` 增加默认关闭的 `path_choice_center`，由独立只读采样器计算位移，owner 发布最多8秒的租约；world、进程、owner身份改变或原生错误会撤销。私有Native72冻结自该提交，33项离线检查通过，尚未在游戏中运行，不能作为发布验收。

审查发现三个尚待解决的边界：同canvas嵌套其他scene仍可能继承外层位移；读取耗时与布局变化尚无完整新鲜度绑定；固定sidecar路径的比较后删除不是原子所有权协议。因此该功能保持私有、默认关闭，不推广到玩家包。只在发现嵌套后计数失败并不能撤销已经继承的矩阵。

只读采样器已改为单个有界队列的daemon worker。关闭时先取消发布、撤销租约，再最多等待0.25秒；阻塞读取不会阻止owner执行native/XR清理，也不会触发ThreadPoolExecutor的解释器退出等待。worker返回后自行关闭只读句柄；若仍阻塞，进程退出释放句柄。session/export记录是否实际join，不能把未join写成已清理。10项监控测试（含阻塞读取）、49项runner及26项诊断导出测试通过；这些是离线生命周期证据。

后续增加2秒采集年龄上限，包含排队、读取、布局计算、序列化和发布前重试。迟到结果不获得新的8秒租约，并撤销上一租约；下次仍可重新采集。12项监控测试通过，含旧结果、验证阶段超时和恢复后的新结果。这解决了旧采集结果被重新授予租期的缺口，但没有证明同一scene的布局在租约期间不变，不能替代原生端布局绑定与嵌套隔离。
