# VR 低帧率：捕获热路径修复与验证边界

2026-10-19。用户在真机 VDXR 中把 VR render scale 调至 0.25 后，游戏立体新帧仍约 40 FPS。该次旧版会话 `analysis/runtime/continuous-stereo-29368-20261019-185437-ce31e05e` 的 24 个玩法状态遥测样本：立体新帧均值 39.94 FPS、游戏 Present 均值 40.13 FPS、OpenXR 循环均值 120.01 Hz；游戏桌面输出仍为 3840×2160，眼部计划尺寸为 768×816。FPS 是新立体帧率，不是头显合成刷新率。

## 定位和修复

原生捕获的每个 owned scene 消费期间有约 5,900 次本进程安全读取和约 3,500 次帧钩子锁路径。旧版用 `ReadProcessMemory(GetCurrentProcess())` 读取本进程内存，并在每个热路径入口使用 `std::recursive_mutex`。渲染成本探针在旧对照中测得每个 owned ticket 的安全读取中位 2.208 ms、帧锁路径中位 8.534 ms、消费区间中位 24.709 ms。这些是 CPU 墙钟区间，类别相互嵌套，不能相加，也不能当作 GPU 耗时。

`tools/native-capture/capture.cpp` 已将本进程安全读取换为有 SEH 保护的局部 `memcpy`，保留读失败返回；帧钩子锁换为 Windows `CRITICAL_SECTION`，保留递归互斥语义。当前默认 DLL 为 `tools/native-capture/build-mounted-fps1/GearsCaptureMountedFps1.dll`，SHA256 `9505245bd8ba18632b6faac1d1c39232be7a069cffbd3164ae0c5e0e9151c07e`，由 `tools/vr-launcher/manifest.json` 引用。该构建同时包含当前 mounted-camera 等功能，未回退其他交付代码。22 项启动预检及相关 native 测试通过。

## 结论和未完成的验收

0.25 缩放只降低眼部渲染尺寸，不会减少数千次本进程读取和锁入口，也不会自动降低游戏的 4K 桌面输出。本次 4K→720p 对照仅改变约 0.6 FPS，不能把 4K 像素填充认定为当前主要瓶颈。捕获热路径是已经测到并修复的主要低帧率来源之一。

当前新构建**尚未在真机 VDXR 中量到新立体帧率**。模拟器新构建仍在约 53–55 FPS，真机中能否摆脱旧版约 40 FPS、是否有独立的运行时/驱动等待或串流限制，须以新 DLL 的 VDXR 玩法会话遥测与实际头显观感分别验收。不能把模拟器对照当作真机修复完成。

2026-10-19 新默认 DLL 的自主 VDXR 测试尝试在游戏启动前被运行时拒绝：`XR_ERROR_FORM_FACTOR_UNAVAILABLE (-35)`，即当前运行时没有可用头显系统。回执为 `analysis/runtime/fps-resolution-4k-vdxr-live-new-30a-20261019.json` 和对应 launcher log；未产生有效玩法样本、未留下游戏进程、用户设置恢复。等待头显连上后仍需完成真机验收。
