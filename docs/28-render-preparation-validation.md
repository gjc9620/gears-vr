# 渲染准备阶段前后验证

2026-10-12，恢复原版的单人关卡 PID 12624，20 秒静止基线。不截图、不改镜头。

## 观察机制

在消费 Hook 的线程局部上下文内观察 0x1fc060 前后，kind=12 只接受同一渲染对象，其他调用照常转发而不记录。调用前保存首视图矩阵到 source_matrix0..31，调用后保存到 matrix0..31；renderer_source0 / 1 在此类别分别保存视图 +8 的前/后关联指针，不沿指针读取历史对象，不认定其类型。

valid 256 / 512 表示前/后矩阵读取成功，8192 / 16384 表示关联指针前/后读取成功。集合、存储和 owner 沿用既有位；完整组合 30592。

`--prepare` 自测通过真实 trampoline 验证参数转发、前后快照、范围外不记录、停止及入口恢复。原模拟函数实际修改两个元素和关联指针。其他五项自测也通过。当前构建 `build-prepare/GearsCapturePrepare.dll`，启动器默认预留八处原生跳板，进入关卡后才激活，另观察两个 DXGI 入口。

## 进一步缩小的写入候选

准备函数 0x1fc376 调用分发器 0x3d8564，局部参数结构保存视图和关联状态指针位置。分发器按设置进入 0x15de10、0xbe6b18 或 0xda44c4 等分支。这三条普通代码路径均把 RDX 作为视图，写入 +0xD0 / +0xD4：水平旧值加偏移两倍除以 +0x50；垂直旧值减偏移两倍除以 +0x54。未动态确定本轮选中的具体分支。

写入后继续进行 SIMD 计算，写入视图 +0x2B0、+0x1A0 等区域，并调用矩阵相关助手。具体矩阵名称、乘法顺序和助手语义尚需确认，不能把改两个数当作完整双目实现。

下一步核对具体分支与派生矩阵关系，再设计左右眼更新方式。尚未新增第二视图或输出立体画面；已有受限真实头动成果保持有效。

## 离线矩阵布局核对

新增 `analyze_matrix_layout.py` 以行向量假设测试视图 +0x70 的前 16 个浮点数：前三行的三维基应正交归一；末行平移应等于负镜头位置乘旋转部分。用转置反算位置，再与同一条场景记录的位置比较，不使用不同帧的堆地址作关联。

此前原版运动 PID 43632 的 9,868 个样本、3,531 组前 16 元素通过；最大正交/仿射误差 4.26e-7，反算位置最大误差 0.0156 游戏单位。当前静止 PID 12624 的 6,881 个样本也通过，位置最大误差 0.0061。后一组矩阵的两个缩放系数比例约 1.777778，按常见透视缩放公式反算水平 FOV 约 80 度。

这些离线结果支持当前 CPU 视图矩阵布局假设；不证明 GPU 常量布局、投影深度映射、全部镜头模式或立体输出。证据另存对应 `-layout.json`，没有为此启用新 Hook 或要求用户重测。
