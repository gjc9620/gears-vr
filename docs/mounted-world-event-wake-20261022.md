# 机枪恢复：原生工作线程事件唤醒

继续推进“无延迟上机枪”。本轮针对恢复准备、提交和交接期间的固定轮询等待修改代码，没有启动游戏、寻找机枪、操作当前用户会话或进行头显测量。

## 行为

原连续会话工作线程每轮末尾固定 `Sleep(20)`，Prepare／Commit 即使已到达也需等下一轮消费。现在等待原有 Stop、Prepare、Commit 事件，等待中的线程可由通知唤醒；没有新增公开控制事件或改变消息授权规则。

Prepare／Commit 仍为 auto-reset 事件。等待器消费信号后仅保留一个待处理回执，由原 poll 逻辑取走；取走之前不再次等待同类句柄，后续信号保留在内核中。Commit 仍先于 Prepare 执行原来的处理检查。事件唤醒本身不接受任何候选：原有不可变文件、进程／owner／创建时间／请求／generation、身份和代码校验、旧 renderer／UI／GPU 排空、世界门禁及姿态截止时间规则保持。

收到有效 Commit、进入交接后，名义等待间隔短时为 1 ms。快速期最多 250 ms，完成提交后保留剩余时间用于首个新图像及 fence 轮询；同一请求的重复信号不会延长窗口。到期后恢复原有 20 ms 间隔，新请求才可开启新窗口。

Stop 事件保持手动复位和优先处理。停止清理阶段继续使用原有 20 ms 休眠，避免持续触发的停止事件引起立即唤醒空转。等待 API 失败进入既有 proof-failure 停止路径。终止诊断增加有界的准备／提交／停止唤醒数和等待失败标记，供之后正常使用时核对。

这里的 1／20／250 ms 是调度策略，不是 Windows 调度精度、完整恢复时间或实体头显黑屏测量。工作线程本身的处理、证书准备、GPU 排空和帧生成仍可能耗时。
