## 中文

# 0.1.0：缩短机枪恢复的身份组装时间

本轮目标是继续缩短上下机枪恢复的 CPU 准备耗时，并保留现有 native 的完整接收校验。用户之后统一验证头显体验；本记录不表示零黑屏或无延迟已获验收。

## 修改

- Anchor 组装对已经加入本次身份表的类和 superclass 使用同次组装值，结束时仍逐个重新读取所有身份和 superclass；组装前、后、最后边界的完整角色／链接／时间戳 guard 均保留。
- UI 组装对本次已完成双读的身份使用有界字典，重复属性和类查找不再逐次打开相同读取链。最终使用完全不经过该字典的读取，重查所有选中对象、当前 registry 槽位、FName 和名称内容；类发现到排序之间的独立重查、脚本、属性、入口和链接核验保留。
- Crosshair 组装使用同次身份提示；其第一次双读仍将每个字段、槽位和名称的精确字节区间加入证书检查表。结束时对整张表逐项做未缓存的实际读取，保留脚本、字节码、原生入口、属性、aim 字段及受控角色链接检查。
- 三处提示只存在于一次函数调用中，不跨准备尝试、进程、reader 或世界保留。公开入口的可选 `reuse_assembly_identities=False` 仅供完整旧读取策略对照，正常路径默认开启。

此次不改变机枪 CameraCache.POV 来源，不将人形 Driver 的眼位替代机枪视点，不改变权威瞄准线，也不绕过 native 世界恢复／GPU 所有权流程。

## 合成检查

`test_assembly_identity_hints.py` 覆盖普通和机枪配置及整段 INI 等价、最终身份／槽位／名称／superclass 变更拒绝、相同 resolver 的下一次调用不沿用旧提示，以及严格布尔参数。已有 UI、Anchor、Crosshair、mounted 集成检查保持通过。

当前工作区的相关 Python 回归共 433 项全部通过，其中三项历史菜单证据检查也已在本地执行。随后仍需在固定运行目录重复核查，避免共享源码改动影响实际测试归因。

在固定合成输入下，UI 的实际读取由 4818 次降到 1171 次（约 75.7%），带 tick roots 和 writer view 的 Crosshair 读取由 9685 次降到 1445 次（约 85.1%）。这些是读取次数，不是头显黑屏时长。
