# 机枪恢复：只读原生类发现

本轮继续推进“无延迟上机枪”。按用户安排，仅进行源码、合成内存和离屏组件检查，没有启动游戏、连接游戏进程采样或操作用户窗口。当前证据证明一段查找工作减少，不证明完整机枪切换已经无延迟。

## 改动

UI 恢复证书需要从对象注册表中发现所需类。原路径已将读取合并为 64 KiB 块和有界 4 KiB 页面，但仍逐对象执行 Python 循环。本轮将排序、对象类指针筛选和 `Class` 名称判断移到原生循环，返回候选对象地址。Python 随后仍执行完整证书构造及所有选中身份、槽位、名称、继承、属性、脚本、代码和链接的实时检查。

新导出 `GearsCaptureDiscoveryClasses` 是同步的发现辅助函数，不在游戏渲染钩子中调用。持续会话的外部 owner 按已信任清单的 DLL SHA256 核对并加载本地模块；普通 idle 观察可先完成预热。读取通过当前 Resolver 的原有只读回调执行，写入目的地仅为 owner 的临时本地结果缓冲。新路径不打开额外游戏进程、不调用游戏函数、不写游戏内存、不操作窗口或 XR 生命周期。

辅助函数按 ABI 版本 1、当前已验证字段布局和小于 400 万项的输入界限工作，每次调用独立创建发现缓存。保留空指针跳过、排序和重复地址行为、读取失败后的块／页／精确范围回退、UTF16 有效性、名称条目索引检查，以及旧名称快照外新槽位的双边注册表检查。明确注册表变化传播为原有 `DiscoveryRegistryChanged`；取消或其他检查异常跨回调返回并拒绝整次采样。

旧构建缺少导出、模块不可用或字段布局不支持时，仍可使用原 Python 发现路径。DLL 哈希不匹配不会加载该代码；恢复候选本身仍受既有 HookEntryAttestation 和清单信任链保护。静态模块加载不提供任何当前游戏身份或图像证明。

## 离线证据

使用同一个候选 DLL，对 100,003 个注册对象、3 个类候选的合成缓冲执行八段交错对照。完整候选列表一致。Python 遍历中位为 **19.87415 ms**，原生遍历为 **3.1421 ms**。该夹具使用本地字节缓冲，包含 Python／原生循环和回调开销，不包含真实游戏 ReadProcessMemory、完整证书准备、GPU 出图或头显黑屏时间。原生路径在此夹具中读取 253 次，Python 路径为 246 次；改善来自逐对象循环开销，而非此夹具的读取次数减少。

**39 项原生／启动前检查通过**，包括独立发现测试和加载实际候选 DLL 的同一 API 测试，覆盖候选及排序、重复地址、不可读块／页回退、名称／名称索引变化、容量／版本界限及回调取消。既有世界门禁、StereoGate、第一人称、瞄准、UI、资源生命周期和三种 D3D12 资源状态下的双眼像素组件检查通过。离屏 D3D12 未启用 debug layer；这些检查不属于游戏或实体头显验收。

**481 项 Python 检查通过**：339 项相关检查启用实际候选 DLL，未跳过原生用例；142 项启动器与打包检查通过。新增检查覆盖人物及机枪完整 UI 配置／INI 字节相等、候选列表和重复项一致、旧名称快照外的有效新槽位及变化拒绝、取消／注册表异常不被隐藏、错误 DLL 哈希不加载代码、未知布局和缺失能力回退。338 项首轮检查中的 4 个未指定候选 DLL 的原生用例曾被显式跳过；最终 339 项检查已传入候选并全部执行。
