# GearsVR 掩体系统需求文档

首次整理：2026-11-08；本次文档核对：2026-11-09。适用对象：玩法实现、集成与验收人员。

目标是在第一人称 VR 中保留原版掩体吸附与移动能力，让玩家通过真实身体动作或左手抓边连续探身，并保证视点、身体暴露、枪口遮挡和受击判定一致。左手拉拽松开后保持虚拟身体位置，重新抓住边缘反向拉动才能缩回；真实头部追踪始终独立生效。

本文汇总现有需求，不表示掩体功能已完成，也不新增开发或测试授权。较新的掩体专项规格优先于早期交互草案；当前代码、局部实验和最终玩法验收分别记录。

阅读导航：第 2 节查看玩家操作，第 3 节查看 24 项功能需求，第 4 节查看中断恢复，第 5 节查看 22 项验收标准，第 7 节查看工程默认与待调参数，第 8 节查看新旧方案取舍，第 10 节查看模块职责。实现进度另见[掩体开发记录](cover-system-development-20261108.md)。

## 需求总览

玩家可以直接用真实站蹲、侧倾和横移探出掩体，也可以用左手抓边拉动身体；两种位移独立叠加。**松开 LGrip 后保持已提交的虚拟身体位置，重新抓边并反向拉动才缩回。** 保持期间真实头部追踪继续生效，左手可恢复其他合法操作。

| 需求组 | 交付行为 | 详细编号 |
| --- | --- | --- |
| 进入与移动 | 保留原版吸附、沿边、换槽及退出；身体面墙，基础眼点受遮蔽，头显自由观察 | CV-01–05 |
| 真实探身与位置叠加 | 真实上下左右位移连续生效；与虚拟拉拽各应用一次；转头不改变拉拽方向，不产生累积漂移 | CV-06–09 |
| 抓边与左手归属 | 左、右、合法上边缘均由左手 LGrip 抓取；连续可逆、松手保持、重抓无跳变，同次按下只归属一个操作 | CV-10–15 |
| 碰撞与暴露 | 完整身体路径及终点合法；头部穿墙遮蔽视野；实际暴露与受击保护对应 | CV-16–18 |
| 瞄准与联合战斗 | 头显观察不改变权威瞄准；枪口受墙体遮挡；支持抓边单手射击、松边后双手支撑及已有换弹流程 | CV-19–21 |
| 跑动与双眼 | 去除游戏附加的跑动晃动，保留真实头动、地形位移与后坐力；过渡连续，双眼使用同版姿态 | CV-22–24 |
| 中断与恢复 | 释放、追踪丢失、暂停、回中、换槽、死亡及读档均按当前身份恢复，旧抓取和晚到结果不能复活或回滚位置 | 第 4 节；AC-16、AC-21–22 |

功能验收按第 5 节的 22 项标准执行；抓取距离、增益等工程初值与待调参数见第 7 节。旧摇杆探身和松手自动收回方案已被替换，取舍见第 8 节。

## 1 范围与依据

### 1.1 本系统范围

- 高掩体、矮掩体的原版进入、吸附、沿边移动、转角换槽和退出。
- 中立遮蔽眼点、身体面墙、头显自由观察，以及真实上下左右探身。
- 左手抓左边缘、右边缘、合法上边缘后的连续拉拽、松手保持和重抓缩回。
- 左手与武器操作的唯一归属，掩体内瞄准、射击、换弹及恢复衔接。
- 头部越墙遮蔽、身体碰撞、身体暴露、受击与枪口遮挡一致性。
- 普通跑动、冲刺和游戏允许的沿掩体跑动的相机稳定。
- 暂停、回中、追踪丢失、死亡、读档和特殊动作接管后的恢复。

普通移动速度、自由站蹲系统、飞扑与子弹时间、完整逐枪交互不在本需求中重新设计。掩体需要与已有武器能力集成；此集成要求不自动扩大为其他武器开发任务。

### 1.3 术语与坐标约定

| 术语 | 本文含义 |
| --- | --- |
| 中立眼点 | 未叠加真实头部位移和主动拉拽时，依据当前人物姿态与掩体几何建立的基础视点 |
| 真实位移 | HMD 或控制器在有效真实追踪空间内的实际平移，保留原始来源及时间 |
| 虚拟偏移 | 合法抓边拉拽已实际提交的身体位移；松手保持的是这一项 |
| 掩体局部左右 | 身体正面朝向当前掩体时的左右，与实时头显朝向无关；上下沿重力轴定义 |
| 身体基准／观察基准 | 前者负责身体面墙，后者延续有效观察方向；两者分别管理，身体转向不强制扭转视野 |
| 已提交位置 | 身体端实际完成并记录的位置；输入请求、查询结果和画面提示均不能替代实际提交 |

## 2 玩家操作与输入

| 场景 | 输入或动作 | 预期行为 |
| --- | --- | --- |
| 进入掩体 | 原版进入或冲向掩体输入 | 保留原版有效吸附，身体面墙，中立眼点受遮蔽 |
| 沿掩体移动 | 既有移动输入 | 保留沿边移动、碰撞及合法转角换槽 |
| 真实侧探 | 头显在现实中向左或右平移 | 连续探出，移回时连续缩回，无需 LGrip |
| 真实上探 | 现实站起或抬高身体 | 随实际头部位置上移探出，无需 LGrip |
| 真实缩回 | 蹲下、弯腰或将头移回 | 随实际位置降低或收回 |
| 左边缘拉拽 | 左手近左边缘，新按下并保持 LGrip，手向右移 | 身体与视点向左探出；手向左移则缩回 |
| 右边缘拉拽 | 左手近右边缘，新按下并保持 LGrip，手向左移 | 身体与视点向右探出；手向右移则缩回 |
| 上边缘拉拽 | 在允许上探的矮掩体上边缘抓取，左手下压 | 身体与视点连续升高；手上抬则下降 |
| 松开 LGrip | 释放左握持键 | 释放边缘锚定，保持拉拽产生的虚拟身体偏移 |
| 重新抓取 | 左手回到合法边缘后重新按 LGrip | 从当前身体位置建立新起点，反向移动可缩回 |
| 掩体内瞄准与射击 | 适用武器的 LT／RT 或既有瞄准、射击输入 | 保留合法武器动作，不附带自动侧探或上探 |
| 退出 | 原版侧面退出或后退退出输入 | 无论中立、抓取或保持偏移，均可正常退出 |

右侧探身同样使用左手 LGrip。右摇杆左右保留既有转向用途，不恢复早期“按住左右探身、松开收回”的映射。旧方案的右摇杆上下站蹲不作为本系统的另一套按键上探入口。

## 3 功能需求

### 3.1 掩体接近与身体基准

**CV-01 原版掩体能力。** 保留原版进入、吸附、沿边移动、侧面退出和后退退出。真实头动或抓边使身体探过边缘，本身不自动注入行走或退出输入。

**CV-02 身体面墙。** 吸附后建立正面朝向当前掩体的身体参照，头显仍可自由观察；不能把原版身体转向直接施加到头显，也不能强制把视野扭回墙面。

**CV-03 合理中立眼点。** 按当前掩体几何、人物姿态和空间余量确定基础眼点。矮掩体中立眼点应位于顶沿以下并有碰撞余量，高掩体按自身几何建立。不能统一使用固定高度，也不能全局压低普通行走视点。

**CV-04 不自动露头。** 在头手位置不变时，抬头角度、LT、RT 均不能额外推高或推出身体。低位基础眼点不限制合法真实上探，不能靠每帧回中抵消真实位移。

**CV-05 移动连续。** 沿边、转角和换槽时复核掩体身份、合法方向和身体位置，结束旧抓取并衔接新基准；旧槽锚点不能继续拉动身体。

### 3.2 真实头动与虚拟探身

**CV-06 完整真实追踪。** 真实站起、蹲下、弯腰、侧倾和横移均可连续探出或缩回，不要求按键或抓边。纯旋转只改变观察方向；旋转伴随的真实平移仍必须保留。

**CV-07 两类位移独立叠加。** 真实头部位移与拉拽产生的虚拟身体偏移分别应用一次。松手保持只固定虚拟偏移，真实头部仍可继续移动；回到原真实姿态后应回到原虚拟偏移位置。

**CV-08 方向与限位稳定。** 左右按面向当前掩体的局部左右定义，上下按重力方向定义；转头不改变拉拽符号。不同墙面朝向下均应正确。合法范围按当前掩体统一身体基准计算，多次重抓不能累计突破总行程。

**CV-09 无累积反馈。** 拉拽输入使用同一真实追踪空间内的左手相对位移。不能用经过身体变换的虚拟手位置反向驱动身体，也不能用手相对头的变化代替手的真实位移。固定输入持续保持时不得逐帧漂移。

### 3.3 左手抓边

**CV-10 抓取准入。** 新抓取必须同时满足当前掩体有效、该方向允许探出、左手追踪有效、左手接近合法可达边缘，以及 LGrip 出现新的按下沿。普通墙面、边缘背面、高墙不可上探顶部及不可达位置不得产生抓取。

**CV-11 连续可逆拉拽。** 左、右、上三个方向均须支持小幅、半探和全合法行程，可在中间位置停止或射击。不能只用阈值触发整段探头动画。

**CV-12 松手保持与重抓。** 松手不自动收回、不清零偏移、不自动解除掩体；左手自由移动不再牵引身体。重抓记录当前身体偏移及当前真实手位，不复用首次起点造成跳变。

每轮处理释放、中断或新手样本前，先同步身体端已经完成的提交。释放先于提交时取消未完成位移；身体已提交后才到达的释放或旧确认不能撤销这次位移，也不能回滚更晚的位置。输入确认只确认身体实际完成的结果，不重复执行移动。

**CV-13 抓取轴锁定。** 工程默认一次抓取锁定一个边缘和一个操作轴；切换边缘须松手重抓。角落附近不得逐帧切换边缘。保留的其他轴偏移仍须通过当前合法范围检查。

**CV-14 可见手部接触。** 抓取期间左手应表现为贴住所抓边缘，身体、右手和武器使用共同身体变换。松开后左手与实时手位连续衔接，具体接触外观须通过实际画面确认。

每个实际可抓边点须有对应左手 GrabPose，按左侧、右侧、合法顶沿的具体表面定义位置、朝向、掌心接触、拇指包握、四指闭合、食指职责、腕和袖口，并覆盖接近、抓稳、拉拽、松手、重抓及脱离的过渡。可复用 authored 基础手型，不能用通用握拳代替逐点适配；保持固定骨长，不靠拉长手臂修贴合。

被动 Snap 只辅助真实接近时的小偏差，不能授予抓边租约或身体移动；获取、保持和脱离应有适当迟滞，避免边界抖动、瞬跳、远距离拉手或抢走已持对象。已有持物优先，旧 Grip 从区外返回不构成新按下。

从能看到接触面的正侧及必要斜角检查游戏镜像和实际双眼画面，分别核对掌、拇指、指根、四指、食指、腕和袖口。遮挡看不清时保持未验收；成功 grant、目标矩阵或 CPU 骨骼数组不能代替贴合画面，头显舒适度另验。尺寸、角度及范围按实际边缘与反馈标定，不扩范围掩盖几何错误。

**CV-15 左手唯一归属。** 抓边、辅助持枪、取弹、装填和机械部件抓取互斥，同一次按下只能触发一个操作。工程默认已持对象继续拥有左手，释放后才允许抓边；抓边期间右手保留单手持枪、瞄准和射击能力。松手保持后左手可重新辅助持枪。

### 3.4 碰撞与战斗一致性

**CV-16 身体合法位移。** 虚拟拉拽经过连续碰撞检查及当前掩体允许范围裁剪，不能将整个人物碰撞体直接传送到墙外破坏吸附。

碰撞检查覆盖从当前偏移到候选偏移的完整身体体积路径及终点占用；先侧探后上探等组合姿态同样适用。零散射线、四角安全或未经认证的矩形范围不能代替扫掠。边缘证据绑定当前 Link／槽位及权限、实体 Actor／Component、碰撞形状与变换代次、接近侧、可抓区间、手部可达路径和采样时相；槽位权限本身不能证明可抓。

查询等待、有效空返回、明确受阻与查询失败分别处理。等待期间保留仍然合法的已提交位置，继续响应真实释放；不把等待当成失败结束，也不使用未知结果放行。碰撞世界变化或旧结果晚到时重新核对来源、起始位置版本和当前占用；同一 Actor 身份不代表空间未变化。被挡后只提交已证明可达的位置，并以该位置及本次真实手位重设起点，反向拉动应立即响应，不能积攒越界位移后跳动。

松手保持期间，每次发布位置前仍需取得当前占用证明。若移动障碍、破坏或槽位变化使原位置不再合法，停止新拉拽及未经认证的身体发布，保留真实追踪并遮蔽不可信视野，通过原版移动／退出链和已认证的短路径恢复。没有合法恢复路径时退出掩体扩展模式；不能直接清零偏移、瞬移回中或将裁剪后的数值当作恢复成功。

**CV-17 头部越墙保护。** 真实头部继续跟踪；穿入实体墙面时遮蔽受阻视野并引导返回合法区域，不能从墙后眼点泄露场景，也不能强制弹回真实头部姿态。遮蔽过渡需头显舒适度验证。

**CV-18 暴露与受击一致。** 虚拟身体和上身暴露、受击区域及保护范围须随实际姿态对应。不能只移动相机，使已经探出的玩家仍获得完全藏好的保护。

实际露出的头、躯干和手臂须按对应命中处理；不能让原版盲射免伤继续保护已伸出的身体。保留正常伤害类型、爆炸例外、护甲、难度和后续伤害流程，不直接写生命值代替。原版单人和多人保护分支分别核对，单人通过不能推广为联机权威通过。

身体发布、物理／命中几何、实际伤害上下文及权威枪口须关联同一有效姿态与模型。渲染骨骼读回不能代替物理和命中消费者的完成证明，一次伤害回调也不能补签此前移动所需的几何证据。仅对已认证骨架映射和本地权威范围启用扩展；骨数相同不能证明骨架兼容，联机能力须另行认证。

**CV-19 瞄准与头部观察分离。** 权威武器方向决定射击，头显改变观察和投影；准星须对应武器瞄准线及场景交点。保留掩体举枪状态独立于 HUD 命中点查询的既有修复，不能因查询缺失就把当前举枪状态改为未瞄准。

**CV-20 枪口遮挡与射击许可。** 眼睛已经探出但枪口仍在墙后时，射击遵守真实枪口遮挡。未露头时是否可盲射按经验证的原版武器规则处理，不统一禁止。若原版开火依赖掩体动作许可，应依据实际暴露与武器状态处理，同时抑制附带的自动镜头位移，不能通过吞掉扳机解决。

稳定半探应可持续合法开火，不能因连续姿态一直被视为未完成的掩体动画而永久等待。适配须同时保留真正的镜像、换枪、装填及特殊武器限制；不得全局关闭动画等待或开火保护。涉及武器特殊释放／取消的联合验证只覆盖该武器已授权接入的能力，不据此扩张逐枪开发范围。

**CV-21 联合战斗。** 支持抓边时单手射击、松边保持后恢复双手支撑、按已有规则换弹、反向缩回与退出。中断不能造成装备丢失或弹药复制。武器模型、准星、枪口、散布及弹着点分别验证。

### 3.5 跑动与双眼视点

**CV-22 去除跑动附加晃动。** 覆盖普通跑动、冲刺和可用的沿掩体跑动，去除游戏步伐额外施加的上下颠簸、左右摆动、点头、摇头、滚转与甩动。固定头显、平地直线运动时，视点沿人物路径稳定前进。 对仍然可用的一人称、三人称 VR 模式分别验收跑动稳定性；不要求为此恢复已停用的视角模式。

**CV-23 保留有效运动。** 保留真实头显旋转和平移、实际位移、坡面台阶高度、主动转向、必要姿态高度及武器后坐力。不能锁头、滤平原始头动、固定世界高度、改变跑速或全局关闭动画来消除晃动。

**CV-24 过渡与双眼一致。** 起停、跑动切冲刺、吸附及退出连续，不突然恢复抖动或甩动。头、身体、手、武器与左右眼使用同一有效基准和提交代次，避免左右眼分用新旧偏移。保留独立左眼历史、原色彩、支持日志和既有 HUD 修复。

## 4 状态与中断恢复

交互层至少需表达以下四类状态；具体代码名称可沿用已有实现。

| 状态 | 含义 | 允许操作 |
| --- | --- | --- |
| 掩体外 | 没有当前有效掩体 | 正常移动、武器与追踪，禁止抓边 |
| 已吸附 | 有效掩体，拉拽偏移回中 | 真实探身、合法新抓取、移动或退出 |
| 正在抓取 | 左手锚定合法边缘 | 连续拉拽、真实头动、右手战斗、松手或退出 |
| 保持偏移 | 左手已松开，合法虚拟偏移仍存在 | 真实头动、重抓、左手其他操作、移动或退出 |

退出和原版特殊动作接管优先于抓边。松手保持不锁定真实头动；退出清理偏移时须连续衔接，不瞬移，也不能由尚未松开的 LGrip 立即重新吸附。

| 事件 | 恢复要求 |
| --- | --- |
| 左手丢追踪或输入过期 | 停止拉拽、解除手部锚定，保留仍合法的偏移；新抓取须先松开再按下 |
| HMD 丢追踪或 XR 会话不可用 | 使用既有恢复显示，停止新抓取，不使用旧手样本继续拉动 |
| 暂停或菜单 | 暂停交互；返回同一有效掩体可保留合法位置，抓取需重新建立 |
| 回中或追踪空间代次改变 | 共同重建头、手、身体和武器参照，解除旧抓取，禁止跨代次计算手位差，保持有效世界位置连续 |
| 摇杆转向改变身体参照 | 结束旧抓取，复核新朝向及掩体范围，不将参考轴变化当作拉动 |
| 转角或换槽 | 结束旧边缘锚定，复核新槽位及允许方向后再抓取 |
| 保持位置被障碍占据或合法范围收缩 | 停止未经认证的新发布，保留真实追踪并按当前几何恢复；无合法短路径时退出扩展，不瞬移至零偏移 |
| 死亡、重载、换图或人物替换 | 使旧掩体身份、抓取锚点和持久偏移失效，新场景重新认证 |
| 剧情、机枪或特殊动作接管 | 交还原动作控制，不向其他相机或人物泄漏掩体偏移 |
| 正常退出或中途失败 | 按身份与当前值复核后撤回本功能拥有的修改，不覆盖其他系统的新值或对象 |

既有材料包含部分掩体认证、低眼点、模拟 HMD 上下位移、纯旋转不误触上探、抓边数学与跑动候选应用的局部结果。完整真实 LGrip 三方向闭环、高低掩体最终遮蔽、碰撞与受击、枪口一致性、跑动过渡及实体头显验收仍未完成。当前功能状态应以具体候选与实际证据更新，不能由历史默认版本或 CPU 通过推断。

## 7 工程默认与待定参数

工程默认沿用专项规格：单次抓取锁定一个轴；已有持物优先；原版允许上探的位置才开放上边缘抓取；拉拽初始增益为 1，并使用既有米与游戏单位换算。这些默认不等于手感已验收。

[2026-10-28 交互合同](cover-specs-20261028/interaction-contract.md)还给出以下可调初值。它们是工程默认，不是原版常量或最终验收阈值；具体实现应核对现有公共层是否有更严格约束。

| 参数 | 合同中的初始默认 | 使用边界 |
| --- | --- | --- |
| 拉拽增益 | 1.0 | 使用真实手位差；不能通过改变增益绕过合法行程与碰撞 |
| 手掌到边缘捕获距离 | 0.10 m | 仅用于新抓取接近判定；保持抓取时不能因正常拉手越过此距离就断开 |
| 歧义候选距离差 | 小于 0.02 m | 没有明确表面归属时拒绝新抓取，不任意选边 |
| 碰撞安全边距 | 0.02 m | 不能代替身体扫掠、终点占用和当前几何证明 |
| 追踪样本时限 | 沿用既有 100 ms 上限 | 保留公共主线更严格的来源限制；新鲜样本不代表碰撞占用有效 |
| 人工基准过渡 | 0.15 s | 仅插值人工基准修正；真实追踪即时叠加，碰撞优先，不跨世界插值 |

以下参数仍需场景测量与实际调校，尚无最终验收数值；已有初值的项目也须验证后再定：

- 近边抓取距离、可达角度及抓取释放滞回。
- 最大侧探和上探行程、身体与墙面余量。
- 虚拟左手接触与松手衔接、拉拽抖动滤波。
- 头部越墙的遮蔽及恢复过渡时间。
- 不同高低掩体、转角和新槽位的基准衔接方式。
- 盲射等武器专用许可与实际暴露状态的对应方式。

原始 HMD 追踪不得套用左手拉拽滤波。任何调参均不得以放宽身份、新鲜度、输入归属、碰撞、释放或恢复约束来替代功能实现。

| 通过抬头角度或瞄准按键自动露头 | 仅真实位置变化或合法拉拽驱动探身；瞄准射击不附带探身 |

## 9 需求实施顺序

建议按既有方案先建立一个低掩体的完整闭环：有效吸附与低位基准、真实上探及缩回、取消自动探头，再接合法上边缘抓取、松手保持与重抓反拉。随后扩展左右边缘、高掩体和转角，最后合入武器占用、枪口遮挡、受击及中断恢复。跑动相机稳定可作为独立修复切片集成。

此顺序用于组织掩体内部实现；项目何时开始掩体、是否进入游戏检查，仍按当前任务授权与统一开发安排执行。

## 10 模块职责与接口边界

本节落实 2026-11-09 主人补充的模块化、解耦要求，是实施约束，不表示下列运行接口均已接通。复用当前公共能力；在当前交付需要时逐步完善边界，不建立另一套输入、追踪、骨骼、相机或装备框架。

| 模块 | 拥有的职责 | 向掩体提供或从掩体消费的数据 | 边界约束 |
| --- | --- | --- | --- |
| 公共追踪与场景身份 | 真实 HMD／手位、输入空间和参考代次、当前人物／世界身份与原始时间 | 同源、带身份和原时间的只读追踪快照；当前掩体键由只读接线适配层补入 | 不运行抓边状态机，不制造探身位移，不因读取刷新旧样本；纯追踪数学不依赖掩体算法 |
| 公共输入与左手仲裁 | 真实按下／释放沿、唯一操作归属和租约生命周期 | 掩体提交合格抓边提案；公共层返回本次归属及释放／失效结果 | 一次按下只消费一次；掩体不直接修改持枪、弹匣、弹药或机械部件的内部状态 |
| 掩体交互与几何规则 | 当前 Link／槽位、边缘选择、拉拽轴、手位起点、请求偏移、松手保持和重抓规则 | 读取当前权限／实体几何；生成带 intent、from-version 和来源键的位移请求 | 可独立计算的规则与几何保持纯计算，不直接调用引擎、写人物／骨骼或管理 DLL／资源生命周期 |
| 游戏对象读取与碰撞适配 | 当前反射布局、原版只读查询、表面与体积路径认证、查询生命周期 | 返回成功／等待／受阻／失败，以及绑定当前身份、形状、变换和采样时相的证据 | 查询证据不是身体写入许可；未知或过期结果不能变为空返回；原版调用遵循现有 owner 与重入约束 |
| 共同身体规划与唯一 Native 写入端 | 固定骨长的全身求解、当前 C0 事务、实际提交账本和恢复责任 | 消费已认证的中立基准、脚位、真实位移及合法虚拟偏移；发布实际完成的身体／视图版本 | 掩体不增加第二个骨骼或人物写入端；原始姿态测量、目标转换、纯求解和实际写入许可分别处理 |
| 原版移动与吸附适配 | 原版进入、沿边、换槽和退出，实际人物碰撞与位移 | 提供当前吸附／移动状态；换槽、退出和特殊动作使旧掩体锚点失效 | 抓边不直接重写移动模块内部状态，不以传送或改变普通跑速代替合法身体移动 |
| 相机与双眼渲染适配 | 最终投影、真实 HMD 应用、受阻视野遮蔽、过渡和双眼一致 | 消费同一身体提交的视图基准、偏移和头部受阻结果 | 不反向产生身体位移，不再次应用 HMD，不用渲染眼点校准中立身体，不新增相机控制链 |
| 公共装备／库存与具体武器 | 持物归属、库存事务、武器原版机械动作、实际枪口和权威射击 | 掩体提供同版身体／暴露／遮挡关联；武器提供当前实例、操作归属、枪口及射击结果 | 公共层不依赖某把枪的实现；掩体不运行无关武器流程，也不被无关武器的 pending／失败状态阻断 |
| 受击与保护适配 | 原命中、保护与伤害消费时相 | 消费同一身体姿态的暴露／保护证据，并保留原始命中与伤害参数 | 不以相机像素代替命中依据，不直接写生命值，不把保护修正扩散到其他人物或未经验证的多人分支 |
| 界面、资源与验证入口 | 提示显示、资源准备／释放、受控输入、录制与证据整理 | 通过现有产品接口取得状态、驱动已授权动作并记录真实结果 | 显示和测试驱动不授予交互许可；产品代码不依赖测试脚本，验证不得以复制的模型代替真实生产规则 |

跨模块数据应携带本次操作真正需要的世界／人物／掩体身份、参考代次、原始时间、输入 token，以及 intent／实际 commit／from-version。接口只交换必要的值、状态和明确证据；不跨模块保存可供下一 Tick 写入的栈指针，也不通过读取或修改另一模块的私有全局状态绕过接口。

依赖方向是“公共身份／追踪／仲裁 → 掩体专属规则 → 查询与身体事务适配 → 同版结果供相机、武器和受击消费”。实际接线由现有集成入口组织，不能形成相机输出驱动身体、视觉吸附授予抓取或显示状态解锁开火的循环。各消费者的等待与失败按其本次操作范围处理，不将一个模块的未完成状态扩散为无关模块的全局阻断。

当前已有的原始 C0 测量、纯目标转换及独立掩体身份读取，只分别证明其自身层次；它们尚未构成上表完整运行闭环。具体已实现、已编译与已验证范围继续记录在 [掩体开发记录](cover-system-development-20261108.md)。
