# 机枪恢复：原生准备阶段的时间戳拒绝回执

本轮继续加强上／下机枪的恢复逻辑。修复一个代码中可复现的停滞条件：Python 只读采样已经区分纯时间戳暂态失败，但原生准备阶段的同类失败仍累计普通失败次数。同一身份连续三次被拒绝后，即使相机时间戳随后稳定，owner 也可能停止为该身份生成新候选。

本轮没有启动游戏、模拟器或操作用户的游戏会话。这个缺口由源代码和离线回放确认，尚不能据此断言它就是某次实际机枪退出／黑屏的全部原因。

## 行为与边界

原生 `bounded_guard` 的五次／200 ms 限制保持。新增分类只接受完整 bracket 明确失败且原因为严格／最终时间戳变化的诊断，外层必须确为尝试耗尽或预算到期。没有尝试、结构或读取失败、超时前实际已经成功的 guard 均不属于此类；失败输出不能发布。

原生每收到一个 Prepare 都先清空 `world_prepare_timestamp_request`。只有该请求因上述纯时间戳原因被拒绝时，状态才记录它的确切请求号。接受、其他失败和早期拒绝保持零值，原有请求／拒绝计数继续更新。原有状态变化机制立即发布这些计数。

owner 只在原有完整 session／owner／进程创建时间检查通过、generation 未变、没有 pending candidate、请求号恰为当前请求、拒绝数恰增加一次、时间戳回执恰等于该请求时使用新分类。缺失字段沿用旧行为，不凭日志文本、失败摘要或宽泛异常类型开启重试。

这一回执只撤回本次时间戳失败占用的一次普通失败次数，保留更早的硬错误计数。前三次按 50／100／150 ms 安排新的完整只读采样，之后按原有有界普通退避继续，避免同一身份永久停在耗尽状态。每次重新生成独立请求与不可变候选，仍须通过全部身份、注册表、代码、相机、UI 和 crosshair 校验；没有重发已接受的 Prepare／Commit 或接受旧采样结果。原生真正接受候选后清空该短重试计数，最终提交仍沿用全部排空／GPU／世界门禁证明。
