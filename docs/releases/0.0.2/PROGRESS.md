# GearsVR 0.0.2 启动修复

2026-10-22。按用户要求，先把当前开发源码完整提交至 `codex/0.1.0`，提交 `963d965b8590555bae31d047bef6ccc27d3e6469`；再从公开0.0.1源码提交 `4b621fc430fa5f96eba3bf70399810d3fd51e202` 创建 `codex/0.0.2`。发布标签和既有0.0.1包保留。

本分支只集成本次启动修复、EXE自动识别、日志保留和0.0.2版本说明。原生DLL冻结为 AdsAnchor2，SHA256 `94b73bb04b6f36d4a4bc16f84f1e95d49a1a3144792e0e41d004ef3b802b4304`；XR冻结为MountedLatency1，SHA256 `0a2b7f7dc6a65f8ee23c255423e5fac841726ac6f2ef9bc249ac8e5f4902d56c`。不移入0.1.0第一人称、Playground或渲染修改。

本机解压0.0.1的最早失败由带下载标记的PowerShell脚本被执行策略拦截引起；读取多账号画质设置还独立复现了旧版只允许一份设置文件的问题。修复仅为启动器拥有的PowerShell子进程指定执行策略，保留系统策略和下载标记；按当前Steam账号选设置，并提供正确Steam App ID子进程环境。启动脚本输出显式捕获、按UTF-8传递，失败时保留原始细节。

修复后的同一套启动脚本已在项目内正版PID47884到达AttractLauncher，35帧预检、229次启动菜单平面提交。owner退出0，prime入口、音频及11个受保护文件恢复通过。未进入关卡；启动前取消的XR退出码为1，有序停止／对象销毁元数据正常，保留该边界，不称作完整VR验收。证据在忽略的 `analysis/retail-portable-startup-fix-20261021/`。

本分支88项debug-launch检查和144项启动器、诊断、暂存、打包检查通过，共232项；其中实际创建带下载来源标记的PowerShell脚本，在PythonCheckOnly模式确认启动器的子进程策略可执行它，不创建游戏。GUI已编译并通过隐藏自检，覆盖EXE同目录、一层Mod子目录、无关工作目录和保存路径优先。

最终包的干净解压、隔离依赖与库存检查继续记录在本目录的打包记录中。

最终解压检查额外发现：GUI的Python定位器未显式指定输出编码，中文目录中的随包Python会被误判无效，转而使用开发机Python。GUI与PowerShell定位器现均为探测子进程设置UTF-8输出和读取编码；最终QA必须断言GUI实际选用解压目录内的Python，不能只看自检退出0。

本地0.0.2包已完成，718个成员，约13.69 MiB。最终中文/空格目录解压后的隔离预检、随包Python选择、下载标记脚本、23项原生启动自检及日志导出均通过。项目根目录正常启动器同步为0.0.2，0.0.1原包与两个分支均保留。产物和SHA256见[打包记录](PACKAGE_BUILD.txt)；尚未上传线上发布。

根目录原启动器窗口保持运行；旧EXE先移入忽略的备份目录，再安装通过最终QA的GUI，文件哈希与ZIP一致。下次重新打开根目录启动器即使用新版，安装回执为 `analysis/release-0.0.2/root-gui-install.json`。
