GearsVR 0.0.2 — Startup compatibility fixes

- Fix the downloaded Windows startup helper being blocked by script execution policy. The change applies only to the launcher's child process.
- Supply the correct Steam application context so the selected retail game can remain in the process started by the mod.
- Select the active Steam account's graphics settings when multiple account files exist.
- Find the game EXE beside the launcher, beside Binaries_x64, or through one mod subfolder, while preserving a valid saved path.
- Keep detailed startup-helper output and show the underlying error in the launcher.
- Keep interpreter probes in UTF-8 so non-English installation paths use the bundled Python correctly.
- Export the latest three startup attempts with stage timings, component fingerprints, Steam child-process context, separate thread/process exit codes and a readable startup-summary.txt, even when VR has not started.

The native renderer and OpenXR application are unchanged from 0.0.1. This is a startup hotfix; the 0.1.0 first-person and Playground work remains on its own development branch.
Retail startup and menu submission were checked in a background simulator test. This does not add physical-headset or later-chapter acceptance. Existing limits remain: DLSS/DLAA off, roughly 2-second mounted-gun transitions, later chapters not fully verified.
See README.txt for installation and update instructions.
