# 主线进度与 V1 验收

2026-10-16 更新。V1目标是第三人称双目VR，UI修正纳入本版，尽量加入可用6DoF。真正的原生左右眼渲染和 OpenXR 对应眼投影已经实现，并有实际游戏、GPU 图像与模拟器提交证据。当前工作是补齐恢复、菜单、剧情和持续稳定性，**尚未完成 V1 验收，也尚未形成可发布包**。不以进程存活、测试数量或模拟器提交计数代替画面与真头显验收。

以清单内路径和 SHA256 为准。更新 Python 分类器不会改变冻结 DLL/EXE 的版本；后续诊断构建也不自动成为玩家默认。模拟器交换链编号修复的 quiet2 与游戏静默启动器 quiet6 是另外两项组件，不能与上述 Native/XR 编号混用理解。

玩家路径已移除 Low/High 固定分辨率档位，按游戏实际分辨率生成同帧 SBS：1920×1080 对应每眼960×1080，3840×2160 对应每眼1920×2160。固定 owned 输出仍属于历史研究，不作为当前路径验收证据。DLSS/DLAA 保持启动、运行时及已认证菜单选择路径的禁用保护；其他预设批量赋值等路径不能据此宣称已全部覆盖。见文档62与 `61-graphics-runtime-lock.md`。

## 当前菜单缺口：9t与9u

9t实际进入设置首页及游戏、显示、画质、声音、输入设置。六类top原先长期被分类为UNKNOWN，XR处于待恢复状态而持续提交0层；这是本轮设置页空白的明确路径，不等于此前所有黑屏根因。

分类修复已把这六类精确菜单纳入既有PAUSE_MENU=3：要求准确的Pause→Options活动栈上下文及top/栈末项一致，陌生页面仍拒绝。9u实际逐页进入、返回，最终设置画面两眼相同，Resume后新票据双目恢复。随后修正UI槽复用缓存、一次有界快照重取，并允许已认证菜单在block1输入阻塞期间继续显示；输入控制及GAMEPLAY恢复仍要求block0。9w正式链路19次状态/显示核对通过，100秒观察覆盖该菜单路径及Resume，未采到零层输出；不代表全部菜单、所有闪烁或真头显已验收。主菜单设置、键位绑定及其他未观察页面仍待采样与认证。见文档69。

9w进一步复现“同进程退出到主菜单→继续游戏”失败：旧controller/camera/level证书失效。后续WorldRecovery5实际通过显式prepare/commit，验证旧候选失效拒绝、新Prepare不继承旧Commit、最终停止完整释放和入口恢复。WorldRecovery6现已接入后台自动检测/调度，实际同进程连续两次主菜单→继续游戏均自行prepare/commit，generation1→2→3，恢复新世界projection，停止清理与入口恢复通过；默认候选未提升。后续MainMenu8以独立WGC完整窗口作为共同二维面板，认证主菜单及两层战役选择；恢复1080p后两次完整循环均恢复新world projection，清理通过。窗口试验得到1081高度时则复现原生GPU发布停止，尚未修复；其他子菜单、加载期和长期稳定验收仍缺，详见文档70。

## V1仍需完成的验收

1. **恢复与黑屏稳定性**：同进程重载、死亡/加载、跨关卡及窗口模式变化后必须恢复真实新图像；区分有意菜单quad、短时保留旧图、持续断帧和空层。首次接入仍有相机等待及准备延迟，不能把running当第一帧。
2. **准星与UI**：真头显检查手枪及其他武器的双眼融合、开镜和换枪、HUD尺寸/位置、字幕与设置菜单；无限远方向修正不等于有限深度命中校准。
3. **剧情与视频**：继续验证实时CameraActor切入/返回、不同流式Level和过场长段；预录视频路线尚未完成。仍不能宣布CG与游玩黑屏整体解决。
4. **第三人称6DoF增强**：此前3DoF反馈不代表完整6DoF。相对游戏相机的头部平移、尺度、回中、跟踪恢复及位移边界仍需实际确认。第一人称身体、双手武器交互等属于后续目标，不作为本版第三人称双目交付的前置条件。
5. **发布与生命周期**：验证干净安装、配置/路径、默认候选提升、长时间运行、正常停止及恢复；处理启动抢焦点。当前本机构建和ignored证据不是发布包，专有衍生资料不得打包。
