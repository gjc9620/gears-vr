# 模型与活动件工作单

2026-10-28，离线交付 v2。对应[12 张规格卡](weapon-cards.md)与[复核报告](interaction-review-v2.md)。本单确定来源、制作结果与之后的标定责任；[5 个 GLB 已交付](../../assets/weapon-6dof/offline-v2/README.md)，没有把提取灰模或 GLB 等同于可加载游戏资产。

## 处理原则与交付合同

原独立组件优先复用；枪上机构优先保留原骨骼、蒙皮、材质和动画层级；只有需要脱离枪体拿在手中且没有已确认独立件时，才建立局部独立组件。主体不重建。跨骨权重或跨骨三角面保留蒙皮，不按最大权重粗拆。

每件资产交付：唯一 ID、来源包／网格／哈希、使用许可属性（游戏内引用／本地提取／原创）、父骨和局部参考系、单位、主抓点、插入轴及入口、活动件枢轴、闭合／开放姿态、接触体积、材质槽、LOD、显隐交接、创建／销毁／GC 责任。以下未测量坐标保持 null，不能用零向量或默认比例冒充标定完成。

原创件统一以米建模；完整弹药以局部 +Z 为底座到弹头／封口方向。导入层承担与原引擎坐标、单位和轴向的唯一转换。原件保持来源坐标，额外记录转换，不能对不同武器各乘一次隐藏比例。接触体积独立于高细节网格；提示遮罩只覆盖当前部件，深度遮挡及双眼显示使用主线实际三维场景路径。

“刚性可分”表示所有相关顶点具有完整单骨权重且面不跨组，不能推出骨的物理用途、游戏碰撞、接触位置或原关节运行行程。仅骨名存在但无自有 LOD0 面，也不等于参考点不可用。

## 原组件与新资产的接入合同

原装填件沿用引擎 StaticMeshComponent／原资源路径，明确唯一所有者。手持阶段取代原“挂人物左手 socket”的固定动画关系；到位后恢复枪上件，解绑手持组件；切枪／死亡清理时恢复原 shadow parent、light environment 和显隐关系，不能遗留挂在旧 Pawn 的组件。

原创件固定使用同一引擎三维组件和资源生命周期，GLB 是制作源。M13 Gnasher 完整实弹是唯一首件加载样本。新几何的静态资源路线已定位到原对象构造、LOD和顶点初始化、原组件、根引用租约及释放fence，并备好输入文件；首件仍需验证当前调用ABI、材质、实际显示与清理。不可为每件模型另建渲染器或用 Quad 替代。具体证据与缺口见[资产后端](../offline-tech-prep-20261028/asset-backend.md)。

原包提取网格、贴图、灰模、动画和反编译文件全部留在忽略的 `analysis/`。资产目录只保存原游戏引用、制作说明和原创件；本次新 GLB 不复制原包顶点或贴图。没有制作或替换游戏候选包。

## 不接游戏即可完成的检查

检查源哈希、骨父子关系、LOD0 三角归属、UV／材质槽与独立件闭合面；原创件检查单位、轴向、命名、法线、封口和包络；输出明确的抓点／运动配置字段与未校准项。最终抓取距离、动作舒适度、实际装填口可达性和头显近看质量留给对应实机阶段，不在本轮伪报通过。
