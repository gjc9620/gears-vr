# 武器与掩体共用合同

这些是两套离线方案的合并决定。只新增实施要求，不改变当前主线M4。

## 一次输入只交给一个动作

| 上下文 | 归属与结果 |
| --- | --- |
| 左手已有支撑、弹匣、弹药或机构租约 | 现有租约继续；不能被掩体抢走。实际松开后才可换对象 |
| 左手空闲、合法掩体边缘、fresh LGrip | 现有唯一仲裁器接受cover请求；抓边时不同时辅助枪或取弹 |
| 同一帧出现多个物理候选 | 先由精确接近／可达性筛选；沿用共享仲裁，不在每个模块各发一次grant；不明确则不开始新动作 |
| 松开掩体LGrip | 先同步已完成身体提交，再释放手；保持虚拟偏移。下一次fresh Grip才可抓弹匣／机构 |
| 右手持手雷 | RGrip负责持有／身体槽，右扳机主动准备和释放；左手释放、追踪中断、换世界不是投掷沿 |
| 装填中按辅助R3 | 同一transaction去重；不重启计时、不补发一件弹药 |
| Troika | 原炮位拥有装备／移动资格；不借用肩部槽和普通换弹，不在炮位状态自动进入cover抓边 |
| 菜单、死亡、剧情、世界切换 | 先按原状态接管，再取消尚未提交动作；已完成库存／投掷／身体移动不回滚成未发生 |

## 扭力弓主动取消的默认入口

此前规格已定义自动中断时的非发射取消，但没有明确玩家主动取消的输入。现固定为：**持有扭力弓且处于本轮Charge时，fresh R3短按取消本轮蓄力**；该按下只生成 `cancel_charge`，不生成ReloadIntent。普通松右扳机仍是发射请求。非Charge状态的R3仍遵循可选装填辅助；R3不是正常换弹前置。

新增 `weapon_torque_bow_interaction.h::cancel_charge(stamp, edge)` 的受限公开入口，校验当前stamp、武器、Charge归属与单调cancel token，再复用私有 `request_abort` 的非发射事务。不要用 `interrupt()` 代替普通主动取消：它包含故障语义。取消成功后等待右扳机真实松开再武装下一次蓄力；重复R3不重入。已进入Fire或已有原shot回执则报告已发射，不退款，也不把箭销毁成取消。失追、切枪等仍使用既定中断链。

此按键只用于明确取消意图，避免玩家为了取消而故意失追或切枪；与L3回中、右摇杆转向和旧L3+R3视角预览组合不并行分派。6DoF上下文继续禁用旧预览组合键。

## 最终开火许可

一个当前武器动作必须同时满足：主线实例与来源有效、右手真正持有、原游戏允许、机械可射击、没有冲突的待提交动作、对应cover姿态／枪口证据有效（若当前在cover扩展中）。

`mechanical_ready`、原 `ShouldDelayFiring`、cover碰撞与权威muzzle是不同证据；不能只检查其中一个。枪口被墙挡住时优先沿原弹道撞墙语义处理，不一律吞掉扳机；不允许把射线起点或投射物出生位置推到墙另一边。弓的正常松键、主动取消、疲劳释放各有独立语义。手雷不套枪械muzzle返回值覆盖。

所有模块共用当前Actor/Weapon/World/registration/lifecycle/reference/space identity；新增 `cover_commit_version`、`basis_generation`、`asset_generation`、`inventory_revision` 是已有身份的补充，不能拿一个frame计数代替所有版本。

## 手雷速度：玩家轨迹与程序位移分离

`grenade_throw.h::GrenadeThrowTracker` 已在原始XR LOCAL米坐标拟合 `grip.position + rotation(grip)*grenade_centre_offset`。这个参考点已经包含转腕引起的圆弧，不能再额外加入一次 `ω_hand × offset`。HMD朝向不参与拟合。

释放采用下面唯一一次转换，符号仅表示数据来源：

```text
p_spawn = committed_body_origin + R_frozen * (p_release_xr - reference_position) * units
v_spawn = R_frozen * v_hand_reference_xr * units + v_base_at_release
```

`R_frozen` 包括本次reference、XR到UE轴映射和当前身体／世界基准的旋转，不包含任意实时头部瞄准。`v_base_at_release` 仅来自已认证的原游戏移动基底速度。若未来支持旋转载具，使用释放点的基底速度且只计一次；未认证的载具投掷保持不支持，不能把未知速度填0冒充静止。

**不从渲染手、掩体拉拽后的世界手或相邻帧camera位置拟合初速。** 掩体保持偏移改变世界出手位置，但不把人工拉拽／平滑交接速度额外注入手雷。正常小步cover平移可更新 `p_spawn` 的已提交原点，原始手窗口仍使用同一坐标空间；方向基准改变、snap turn、recenter、世界／Pawn／武器代变、追踪间断则废弃速度窗口并重新准备，不能混合两套轴。

有效低速／静止主动释放仍能投出：去掉当前内核的0.5 m/s和4 cm玩法门槛，保留样本数、时间跨度、有限值、连续性及最大速度检查。静止Init方向使用手中物体方向，不归一化零速度，不改用头部方向。只有原Spawn／弹耗／Init回执成功才把held交给实际弹体。

原弹体继续拥有重力、反弹、停止、贴附和引信。预览如保留，只用本次拟合初速和原世界重力绘制第一段预测，遇到墙、反弹／摩擦或动态目标时不宣称完整轨迹精确。不得为了显示原抛物线而再把 `SimulationDir`／默认Speed写回实际发射。

## 两类提交账本的边界

库存账本在原库存确定提交后推进；cover账本在身体消费者确定成功后推进。两个模块均不能把“尚未ack”解释成“尚未发生”。输入开始前先读当前已提交版本，再处理release/cancel；取消只废弃待执行请求。未知调用结果先读回，不能重复扣弹、重复spawn或重发身体位移。

后端消费异常保留恢复债务；只恢复自己仍拥有且比较匹配的修改。世界或对象消失不授权在旧指针上恢复。正常放手、等待查询、调用失败和来源过期分别记录；不要将它们都映射到一个会清空所有状态的abort。

## 提示和新资产

黄色提示由当前唯一动作owner选择，只显示当前可操作部件；cover抓边、换弹和弓取消不能同时发布互相冲突的提示。机械到位反馈与库存提交反馈分开，原函数未接受时不显示已补弹。

模型后端统一使用引擎世界三维组件，与场景深度和双眼投影一致；不再保留“也许另建Native绘制器”的并行方案。原创资源创建能力尚未验证时，禁止用Quad或假道具冒充完整装填；已制作GLB和原件语义继续保留。技术风险和首件工作见 [资产后端](asset-backend.md)。
